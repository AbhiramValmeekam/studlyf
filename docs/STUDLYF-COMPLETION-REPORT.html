01

What already existed

The starting assumption was that the platform was mostly unbuilt. The audit found the opposite, and the plan was reshaped around it: rebuilding working features is exactly the failure mode the specification warns against.

  • All five ecosystems already had backend modules with Zod-validated routes, real database persistence and per-ecosystem authorization — identity and RBAC (§1–5), builder (§6–12), organization (§19–25), HR (§26–33), founder (§34–36, 44), investor (§46–49), STUD Hub, résumé and portfolio (§51/53/54), admin CMS and audit logs (§61–62, 64, 92), and per-ecosystem onboarding (§77).
  • All five already had frontend route trees, guarded by RequireEcosystem and RequireAccount.
  • The test suite stood at 203 passing tests across 15 files — a green baseline that every workstream had to preserve and extend.
02

What was implemented

Four workstreams, each closing a gap the audit confirmed as genuinely absent.

A · Founder workspace depth (§37–43, §45)

The strategy workspace was a set of flat strings. It now holds structured, persistable builders: the eleven-section pitch deck, a market analysis with TAM/SAM/SOM, a competitor array, the nine-block business model canvas, and a go-to-market plan — all additive, so every word a founder had already written stays visible. Traction gained a dated tractionHistory series so growth is a line rather than a snapshot. The readiness scorer was updated in the same change, because it reads these fields.

B · Public pages, visibility and real certificates (§18/§68/§81/§82)

Certificates are now entities rather than something derived on the fly: a certificates collection with a unique verification code, issued when results are finalised, and a public unauthenticated GET /certificates/verify/:code. Public URLs were added for builders, projects, organizations and published startup pages, each resolved without an account and each backed by an allow-listed serializer. A founder's startup gained a stable public handle and an explicit audience setting, so nothing becomes public without the founder opting in — and the handle never changes when they do.

C · Career roadmap and STUD OTT (§52, §55)

Both were entirely absent. The roadmap maps a target role to required skills and computes a personal plan by diffing against the builder's own profile — rule-based only, with no AI provider named anywhere (§90); the service is the seam a model would later plug into. STUD OTT is its own content shelf with videos, articles, series and short courses, plus per-viewer progress that survives sign-out.

D · Cross-ecosystem search and generic saves (§56, §57)

Search covered opportunities and resources only. It now reaches builders, founders and startups, organizations and projects — every new scope gated by the same visibility predicate the entity's own public page uses. Saving was investor-to-founder only; it is now one platform-wide saved_items table serving twelve entity types, with the investor shortlist migrated onto it so there is one mechanism, not two (§96).

08

New backend modules

Four new modules follow the established shape — repository, service, Zod schemas, routes — and one was extended.

  • certificates — issue and verify; the public router is the only anonymous one.
  • roadmaps — catalog, the rule-based plan diff, and step completion.
  • ott — the shelf, the viewer's progress, and an admin router.
  • saved — the platform-wide bookmark table, with a registry that teaches it how each of the twelve entity types is resolved.
  • search — extended: a scope table where each entity contributes its visibility predicate and its own card shape.
09

Authentication changes

None. The session mechanism, opaque cookies and the account model are untouched. What changed is placement: every new per-viewer route is mounted before the public cache group and marked noStore, so no viewer-specific response can be served from cache to someone else.

10

RBAC changes

None to the role definitions. New capabilities reuse the existing gates: admin CRUD for roadmaps and OTT behind the admin guard, builder roadmap behind the builder ecosystem, and saved items behind a plain session because a bookmark list is neither role- nor ecosystem-specific.

19

Search

Unified search now answers six groups in one request. Two rules govern every scope, and both are enforced in code rather than by convention.

Search never widens visibility

A scope's match is the same predicate the entity's own public page uses — public profiles, verified organizations, discoverable projects — because search is unauthenticated and cached, so anything appearing there is world-readable. Suspended accounts are excluded from every profile scope.

A card is not a document

Each scope returns the entity's own result-card shape, shared with that entity's list views. Contact details, workspaces and private fields never enter the payload, and the tests assert their absence rather than trusting the serializer.

A single id rides alongside each card so a result can be bookmarked. It is deliberately not part of the card shape, so no other consumer of that shape inherits a database identifier.

The new coverage asserts behaviour rather than shapes:

  • A private builder profile never appears, whatever the query — asserted as an exact set, not a substring check.
  • Cards carry no bio, userId, workspace or contact email.
  • Saving twice is one row; unsaving twice is not an error; an unpublishable target cannot be saved at all.
  • A bookmark whose target is unpublished disappears from the list while the row survives, so republishing restores it rather than losing it.
  • The investor shortlist and the general saved list are provably the same table.
  • An unknown scope, an unknown entity type and a malformed id all return 400; a nonexistent target returns 404.

23

Remaining external integrations

  • Certificate document generation stays an interface, as specified — the credential and its verification are real, but no PDF renderer is faked. A generator plugs in behind the existing seam.
  • Email continues to use the existing mailer abstraction. No queue or background-job runner was introduced, because nothing in this pass produced work that needs one.
  • AI is deliberately absent from the career roadmap. The specification forbids faking it, so the plan is rule-based end to end and no provider is named anywhere in the code or copy.
24

Known issues and deviations

These are deliberate omissions and open items, recorded rather than quietly dropped.

§78 — global ecosystem switcher: not built

By decision; an earlier instruction overrode it. /choose and the logo remain the switching paths. The stale copy that referred to a top-bar switcher has been corrected.

§97 — route map: not renumbered

Existing routes keep their current paths. Only genuinely new pages were added, so no link anybody has shared breaks.

Out of scope for this pass

Moderation breadth (§63), platform analytics (§65), data export (§80) and feature flags (§94) are confirmed absent and remain open items for a follow-up. Email and background jobs (§59/§91) stay as they are pending evidence that a queue is needed.

Browser verification is outstanding

The full API round-trips were verified against a running server: a search result saved, listed with its real link and its card, counted, and removed. The UI for the new pages passed the build but has not been driven in a real browser in this environment, so layout and interaction on /saved, /ott and the new scope chips remain visually unconfirmed.

Two pre-existing traps worth knowing

The development database on this machine predates the current seed, so it holds one public builder and no public founders or organizations — search scopes that correctly return nothing there are not broken. And the second seeded builder logs in as nova@studlyf.local using the standard developer builder password; there is no separate credential key for it.
